# 研发投入滞后项的季节性偏差分析与修正补丁 (Bugfix: Quarterly Lag Alignment)

## 1. 缺陷回溯 (The Insight)

在起初的特征构造脚本 `02_variable_construction.py` 中，我们为建立滞后一期研发投入（H2验证核心）使用了如下代码：
`df.groupby('Stkcd')['ln_RD'].shift(1)`

**该做法在“非连续的季度/非平衡面板数据”中存在逻辑漏洞：**
数据清洗阶段（丢弃含有缺失值行）后，同一家公司的连续记录在时间轴上可能产生空洞。机械的 `shift(1)` 只是拉取数据框内的“上一行”，当碰到如 `2020-03-31` 的上一行直接变成了 `2019-03-31`，便会错误地把“滞后一年”的数据作为“滞后一季度”。

此外，财务报表中的研发投入（R&D）、收入和利润等数据往往是**累计值**。将不同季度的累计值直接平移不仅缺乏时间精度，且季报（Q1）与年报（Q4）间天然存在口径与确认周期的季节性波动（Seasonality）。

## 2. 修正方案 (The Solution)

为保留珍贵的大规模样本，我们坚持**季度分析框架**，但实施严格的修复：

1. **精准时间平移 (DateOffset)**：
   利用 `pd.DateOffset` 替代 `shift`。在计算滞后项时，强制规定“只有当上一条记录的日期刚好等于当前日期减去指定的时间间隔时，才赋值，否则为 `NaN`”。由于是累计值，最科学的做法是**平移一年（滞后4个季度：4 quarters / 1 year）**，用去年同期的研发投入来衡量资本对于创新的滞后反馈。考虑到我们探讨的是“前期研发对当期估值的影响”，此处修正为：`Lag_1_ln_RD` 定义为**前一年同季度的研发对数**。

2. **季度固定效应 (Quarterly FE)**：
   在基准回归脚本 `05_baseline_regression.py` 中，除了 `Entity` (控制公司不变质地)效应，引入 `Time` (时间) 特效往往不足以平滑季度波动。我们需要把 `Quarter` 直接提取出来作为单独的分类控制变量，或者确保面板时间维中融合了年份与季度的标识，使得 `PanelOLS` 能自动过滤掉第四季度的“财报突击效应”。

2. 重写 `src/05_baseline_regression.py` ，控制季度异质效应。
3. 补充运行对应脚本生成新的核心面板数据。
